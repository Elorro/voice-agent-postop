# salen de `pip freeze` tras resolver
#
#     pip install fastapi 'uvicorn[standard]' chromadb httpx python-multipart \
#                 pypdf cryptography
#
# dentro de `python:3.12-slim` (misma base que el Dockerfile), el 2026-08-09.
# El build vuelve a correr `pip freeze` y aborta si lo instalado no coincide
# con este archivo: si algo aquí estuviera inventado, el build falla.
#
# Directas: fastapi, uvicorn[standard], chromadb, httpx, python-multipart, pypdf,
# cryptography. Todo lo demás es transitivo. `torch` no aparece ni puede aparecer:
# llevaría la imagen a 2-5 GB. El embedder corre sobre onnxruntime, que es CPU y
# pesa ~58 MB.
#
# `python-multipart` entró en el sub-paso 3.1: FastAPI lo exige para leer un
# `multipart/form-data`, que es como sube el audio el cliente. Sin él, el
# endpoint del turno no arranca — y falla al importar, no al recibir la primera
# petición, así que no puede pasar inadvertido.
#
# `pypdf` entró en el sub-paso 3.2: la consola de administración indexa PDFs
# subidos en caliente, así que la extracción de texto tiene que estar DENTRO de
# la imagen, no solo en el script de indexación del corpus. Es Python puro, 378 kB
# de rueda y cero dependencias transitivas.
#
# `cryptography` (+ `cffi`, `pycparser`) entró por una MEDICIÓN, no por gusto: un
# documento del corpus —breast_cancer/Herramientas-Tecnica-Cancer-cuello-uterino-
# 2018.pdf— viene cifrado con AES y contraseña de usuario vacía (el patrón normal
# de los PDF gubernamentales que solo restringen la impresión). Sin esta
# dependencia, pypdf falla con `DependencyError: cryptography>=3.1 is required` y
# 14 páginas de guía colombiana quedan fuera del índice sin que nadie se entere.
# Coste medido: 4,52 MB de rueda de `cryptography` + 0,26 MB de `cffi` y
# `pycparser`, sobre un presupuesto de imagen de 400 MB con ~80 MB de holgura.
# La alternativa —descartar el documento— era gratis y peor: un hueco silencioso
# en un corpus de 107.
